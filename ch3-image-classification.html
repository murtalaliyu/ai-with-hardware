Technical Documentation

Detailed reference for ch3-image-classification.py: a from-scratch convolutional neural network (CNN) that classifies images as cat or dog, with an interactive menu for retraining, loading a checkpoint, uploading images on the fly, and evaluating the test set.

Binary classification Keras / TensorFlow Interactive menu loop On-the-fly upload 128×128 RGB

1. Overview

The script implements an end-to-end image classification workflow: data loading with augmentation, CNN construction and compilation, training with early stopping and checkpointing, test-set evaluation, and single-image prediction via a file-upload dialog.

From-scratch means the network is defined layer-by-layer and trained from randomly initialized weights on the project dataset only. It does not use a pretrained backbone (e.g. MobileNet / ResNet / VGG).

The application runs in an infinite menu loop until the user chooses Quit. The in-memory model persists across menu choices, so users do not need to restart the process after each action.

6. Model Architecture

Built in build_model() as a Keras Sequential stack. Convolutional blocks learn hierarchical features; a dense head outputs a single sigmoid probability for binary classification.

Layer stack

StageLayersRole
Block 1 Conv2D(32) → BatchNorm → MaxPool2D Low-level features (edges, color, texture)
Block 2 Conv2D(64) → BatchNorm → MaxPool2D → Dropout(0.25) Mid-level patterns
Block 3 Conv2D(128) → BatchNorm → MaxPool2D → Dropout(0.25) Higher-level parts (ears, eyes, legs)
Block 4 Conv2D(256) → BatchNorm → MaxPool2D → Dropout(0.25) Richest feature maps before flattening
Head Flatten → Dense(256) → BatchNorm → Dropout(0.5) → Dense(1, sigmoid) Map features to P(dog) ∈ [0, 1]

Design choices

  • Filter growth (32→64→128→256): as pooling reduces spatial size, more channels capture richer combinations of features.
  • padding='same': preserves spatial dimensions through each convolution before pooling.
  • BatchNormalization: normalizes layer activations within a batch for more stable, often faster training.
  • Dropout: randomly zeroes units during training to reduce overfitting (0.25 after mid/late conv blocks; 0.5 after the dense layer).
  • Sigmoid + binary crossentropy: standard setup for two-class problems with a single output unit.

Compilation

SettingValueRationale
Optimizer Adam, learning_rate=0.0005 Adaptive per-parameter steps; slightly below Adam’s default 0.001 for stability with BatchNorm and augmentation.
Loss binary_crossentropy Matches sigmoid binary output
Metric accuracy Primary reported performance measure

7. Data Pipeline

Training (option 1) uses ImageDataGenerator with on-the-fly augmentation. Validation and test generators apply rescale only so metrics reflect unmodified images. User uploads (option 3) are resized and rescaled inside predict_single_image with no augmentation.

Training augmentation parameters

ParameterValueEffect

height_shift_range0.15Vertical shift up to 15% of height

horizontal_flipTrueRandom left↔right flip (valid for cats/dogs)

Batch / label settings

  • target_size=IMG_SIZE — must match model input_shape
  • batch_size=32
  • class_mode='binary' — labels are 0/1 for a single sigmoid unit
  • shuffle=False on validation/test for stable evaluation order

8. Training

Implemented in train_model() (menu option 1). It builds a fresh model, prints model.summary(), fits for up to 40 epochs, evaluates validation accuracy, and returns the trained model object so the menu loop can keep using it. 

model.fit(
    training_set,
    epochs=40,
    validation_data=validation_set,
    callbacks=[early_stop, checkpoint, reduce_lr]
)
Epochs = 40 is a ceiling. With EarlyStopping, training often ends earlier once validation loss plateaus. After training finishes, control returns to the menu — you can immediately use option 3 or 4.

9. Callbacks

CallbackKey parametersBehavior
EarlyStopping monitor='val_loss', patience=8, restore_best_weights=True Stops when validation loss stops improving for 8 epochs; restores weights from the best epoch (not the last).
ModelCheckpoint filepath=MODEL_PATH, monitor='val_accuracy', save_best_only=True Writes best_model.keras whenever validation accuracy improves.
ReduceLROnPlateau monitor='val_loss', factor=0.5, patience=3, min_lr=1e-6 Halves the learning rate when validation loss stalls, allowing finer updates before EarlyStopping ends training.
Note on monitors: EarlyStopping / ReduceLROnPlateau watch val_loss; ModelCheckpoint watches val_accuracy. These usually move together but are not identical—the checkpoint on disk is the best accuracy snapshot, while in-memory weights after EarlyStopping are restored by best loss.

10. Loading a Saved Model

load_saved_model() (menu option 2, and optional startup auto-load) checks that MODEL_PATH exists, then calls Keras load_model(). If the file is missing, it raises FileNotFoundError instructing the user to retrain first.

Loading skips the expensive fit() loop. The returned model stays assigned to the loop’s model variable for subsequent predictions and test evaluation.

11. Upload & Predict (Option 3)

Option 3 lets users classify an arbitrary local image without restarting the app.

Flow

  1. require_model(model) — abort with a message if no model is loaded
  2. choose_image_file() — open a Tkinter file dialog filtered for common image types (.jpg, .jpeg, .png, .bmp, .gif, .webp)
  3. If the dialog is cancelled, prompt for a typed path (quotes are stripped); empty input cancels the prediction
  4. predict_single_image(model, path) — resize to IMG_SIZE, rescale to [0, 1], predict
  5. Print label and confidence percentage, then return to the menu

Prediction details

  • model.predict returns shape (1, 1); the scalar is treated as P(dog)
  • If P(dog) > 0.5 → label Dog with confidence = P(dog); else → label Cat with confidence = 1 − P(dog)
  • Returns a tuple (label, confidence); confidence is in [0, 1]

12. Test Evaluation (Option 4)

evaluate_test_set(model) builds a rescale-only generator from ./ch3-dataset/test_set and runs model.evaluate, printing test accuracy. This is no longer automatic after every run; it is an explicit menu action so users can train/load once and evaluate when ready.

Optional batch visualization

predict_and_display_images(model, image_files) remains available as a helper for a 3×3 matplotlib grid. It is not wired into the menu by default; call it from a modified script or interactive session if needed.

Typical workflows

  • First run: choose 1, wait for training, then use 3 to classify photos or 4 to score the test set.
  • Later sessions: accept auto-load (or choose 2), then repeatedly use 3 to upload images — no restart required.
  • Custom photos: option 3’s dialog accepts JPEG, PNG, and other common formats; typed paths also work if the dialog is cancelled.

15. Expected Performance

On this cats-vs-dogs setup with the improvements in this script (128×128 inputs, augmentation, BatchNorm, longer training with callbacks), validation accuracy around the high 80s (e.g. ~89%) is a strong result for a from-scratch CNN. Chance baseline for balanced binary classes is ~50%. Transfer learning with a pretrained backbone typically reaches the mid–high 90s.

16. Limitations & Notes

  • Class index mapping (which integer is cat vs dog) depends on folder name sort order from flow_from_directory. Confirm with training_set.class_indices if predictions look inverted.
  • Option 3 needs a display environment for the Tkinter dialog. On headless machines, use the typed-path fallback (or run where a GUI is available).
  • Retraining overwrites best_model.keras only when a better val_accuracy is reached during that run’s checkpoints.
  • GPU is optional; CPU training is slower but supported for TensorFlow on Windows (native GPU support varies by TF version).
  • The menu loop catches training/load/eval errors and returns to the menu instead of crashing the process, so one failed action does not force a restart.
