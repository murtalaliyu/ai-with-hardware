Technical Documentation

Line-by-line reference for ch4-finger-detection-pc.py: a PC-side vision pipeline that detects hands with MediaPipe, counts extended fingers, and streams results over serial UART to a STEPico microcontroller.

OpenCV MediaPipe Hands Serial UART STEPico companion Real-time webcam

1. Overview

This script runs on a Windows (or other desktop) PC. It opens the default webcam, runs Google MediaPipe’s hand-landmark model on every frame, decides how many fingers are extended on each detected hand, draws the skeleton overlay, and sends compact command characters to a STEPico board so that onboard LEDs can mirror the finger counts. Serial I/O is wrapped in try / except / finally so the COM port and camera are released on quit, Ctrl+C, or port errors.

Companion firmware

The microcontroller side is ch4-finger-detection-stepico.py. It listens on stdin (USB serial), interprets characters such as 1–5 finger counts and control letters L, R, V, and drives two banks of five LEDs (left / right hand).

Webcam frame captured via OpenCV
BGR → RGB; MediaPipe Hands inference
Landmark geometry → finger count per hand
Draw overlay; send serial commands
Stack info panel; show window; repeat

2. System Architecture

LayerComponentResponsibility

Vision ML mp.solutions.hands.Hands Detect up to two hands; output 21 landmarks each
Geometry distance / angle helpers Classify each finger as straight or bent

5. calculate_angle (lines 13–30)

Computes the interior angle ∠ABC where b is the vertex (typically a PIP joint) and a / c are the adjacent joints (MCP and DIP). A nearly straight finger yields an angle close to 180°; a bent finger yields a smaller angle.

Line 13 
# Calculate the angle formed by a-b-c, where b is the vertex

Documents the geometric interpretation of the three arguments.

Line 14 
def calculate_angle(a, b, c):

Function signature: three landmark objects a, b, c.

Lines 15–16 
AB = (a.x - b.x, a.y - b.y)     # Vector from b to a
BC = (c.x - b.x, c.y - b.y)     # Vector from b to c

Builds two 2D vectors from the vertex b. Note the comments say “from b to a” / “from b to c”, which matches the subtraction order (a − b and c − b).

Lines 18–19 
# Calculate the dot product of the vectors
dot_product = AB[0] * BC[0] + AB[1] * BC[1]

Dot product \(\mathbf{AB} \cdot \mathbf{BC} = |\mathrm{AB}|\,|\mathrm{BC}|\,\cos\theta\). Index [0] is the x-component; [1] is y.

Lines 21–23 
# Calculate the lengths of the vectors
magnitude_AB = math.sqrt(AB[0] ** 2 + AB[1] ** 2)
magnitude_BC = math.sqrt(BC[0] ** 2 + BC[1] ** 2)

Euclidean norms of each vector (same formula as calculate_distance but from origin of the vector).

Lines 25–26 
# Calculate cos(theta)
cos_angle = dot_product / (magnitude_AB * magnitude_BC)

Isolates \(\cos\theta\). If either magnitude is zero (degenerate / coincident points), this would raise ZeroDivisionError; in practice MediaPipe landmarks for a real hand are distinct enough that this is rare.

Lines 28–30 
# Use arccos to calculate the angle in degrees
angle = math.degrees(math.acos(max(-1.0, min(1.0, cos_angle))))
return angle

Clamps cos_angle into [-1, 1] before math.acos. Floating-point rounding can push the cosine slightly outside that domain, which would otherwise raise ValueError. math.degrees converts radians to degrees; the function returns that scalar.

6. is_finger_straight (lines 32–41)

Heuristic: a finger is “straight / extended” if its tip is farther from the wrist than its MCP (knuckle) joint. When the finger folds toward the palm, the tip moves closer to the wrist and the inequality fails.

Line 32 
def is_finger_straight(landmarks, finger_tip_index, finger_mcp_index, wrist_index=0):

Parameters:

  • landmarks — sequence of 21 MediaPipe hand landmarks
  • finger_tip_index — landmark index of the fingertip (4, 8, 12, 16, or 20)
  • finger_mcp_index — MCP index for that finger (1, 5, 9, 13, or 17)
  • wrist_index=0 — wrist landmark; MediaPipe always places the wrist at index 0
Lines 33–36 
# Determine if a finger is straight (based on distance)
wrist = landmarks[wrist_index]
finger_tip = landmarks[finger_tip_index]
finger_mcp = landmarks[finger_mcp_index]

Resolves the three landmarks used by the distance comparison.

Lines 38–41 
tip_to_wrist_distance = calculate_distance(finger_tip, wrist)
mcp_to_wrist_distance = calculate_distance(finger_mcp, wrist)

return tip_to_wrist_distance > mcp_to_wrist_distance

Returns True only when the tip is strictly farther from the wrist than the MCP. Equal distances return False (finger not counted as straight).

7. is_finger_bent (lines 43–48)

Complementary heuristic based on joint angle at the PIP. Uses MCP → PIP → DIP as the three points for calculate_angle.

Line 43 
def is_finger_bent(landmarks, mcp_index, pip_index, dip_index):

Arguments are landmark indices for the metacarpophalangeal (MCP), proximal interphalangeal (PIP), and distal interphalangeal (DIP) joints of one finger.

Lines 44–45 
# Determine if a finger is bent (based on angle)
angle = calculate_angle(landmarks[mcp_index], landmarks[pip_index], landmarks[dip_index])

PIP is the vertex; angle measures how open the finger chain is.

Lines 47–48 
# Consider the finger bent if angle is less than 160 degrees 
return angle < 160

Threshold of 160°: angles below this mean the finger is considered bent. A fully extended finger is near 180°, so 160° allows a small amount of natural curvature before classifying as bent. Returning True means “bent.”

8. count_fingers (lines 50–65)

Combines both heuristics for all five digits. A finger is counted as “up” only if it is not bent and is straight — both tests must pass.

Lines 50–51 
def count_fingers(hand_landmarks):
    landmarks = hand_landmarks.landmark

Accepts a MediaPipe NormalizedLandmarkList. .landmark is a list/repeated field of 21 NormalizedLandmark objects.

Lines 52–63 
finger_states = [
    # Thumb
    not is_finger_bent(landmarks, 1, 2, 3) and is_finger_straight(landmarks, 4, 1),
    # Index
    not is_finger_bent(landmarks, 5, 6, 7) and is_finger_straight(landmarks, 8, 5),
    # Middle
    not is_finger_bent(landmarks, 9, 10, 11) and is_finger_straight(landmarks, 12, 9),
    # Ring
    not is_finger_bent(landmarks, 13, 14, 15) and is_finger_straight(landmarks, 16, 13),
    # Pinky
    not is_finger_bent(landmarks, 17, 18, 19) and is_finger_straight(landmarks, 20, 17)
]

Builds a list of five booleans (one per finger). Index mapping:

FingerMCPPIPDIPTip
Thumb1234
Index5678
Middle9101112
Ring13141516
Pinky17181920

For each finger: not is_finger_bent(...) requires the MCP–PIP–DIP angle ≥ 160°, and is_finger_straight(...) requires tip farther from wrist than MCP. Python’s and short-circuits, but both sides are still typically evaluated when the finger is extended.

The thumb uses the same MCP/PIP/DIP pattern as other fingers (indices 1–3), even though anatomical naming for the thumb differs (IP instead of separate PIP/DIP). The heuristic is approximate and viewpoint-dependent for the thumb.
Line 65 
return sum(finger_states), finger_states

sum on booleans treats True as 1 and False as 0, so the first return value is an integer count 0–5. The second return is the raw boolean list. Callers currently discard the list with _.

9. Hand Landmark Map

MediaPipe Hands always returns 21 landmarks in a fixed topology. Index 0 is the wrist; each finger is a chain of four joints ending at the tip.

0Wrist
1–4Thumb (CMC→tip)
5–8Index
9–12Middle
13–16Ring
17–20Pinky

Coordinates are normalized to the image: x and y are typically in [0, 1] relative to frame width/height; z is relative depth (not used here).

Lines 98–101

    serial_connection = serial.Serial(port, baudrate, timeout=1)

Initializes serial_connection to None so the finally block can safely test whether a port was opened. The try opens COM4 at 115200 baud with timeout=1 (1-second read timeout). Write traffic in this script does not rely on reads, but the timeout avoids indefinite blocking if something later calls read. Default 8N1 framing still applies (PySerial defaults).

If the port is wrong, missing, or already held by Thonny / another python.exe, serial.Serial raises serial.SerialException, which is caught later (see §16).

14. Serial Protocol (lines 141–153)

After vision processing, the PC encodes state as one or more ASCII characters for the STEPico firmware. The microcontroller pairs a hand-select digit ('1' or '2') with a following finger-count digit.

Lines 141–151 
if len(finger_info) != 0:
    if len(finger_info) > 0:
        serial_connection.write(('1' + str(finger_info[0])).encode())

    if len(finger_info) > 1:
        serial_connection.write(('2' + str(finger_info[1])).encode())
    else:
        serial_connection.write(('R').encode())

else:
    serial_connection.write(('L').encode())

Behavior by case:

ConditionBytes writtenIntended STEPico effect
≥1 hand '1' + digit of hand 0 count (e.g. b'13' for 3 fingers) Select left LED bank, then light that many LEDs
≥2 hands '2' + digit of hand 1 count Select right LED bank, then light that many LEDs
Exactly 1 hand After hand-1 update, also b'R' Firmware treats R as “turn all right LEDs on” (test / fill)
0 hands b'L' Firmware treats L as “turn all left LEDs on”
The inner check if len(finger_info) > 0 is redundant inside if len(finger_info) != 0 — both mean the list is non-empty. Also, when no hands are detected the script sends L (all left LEDs on) rather than turning LEDs off; that matches the STEPico branch for 'L' but may surprise operators expecting a blank display.
Line 153 
serial_connection.write(('V').encode())

Always writes the character V after the hand updates. The companion STEPico script shown in this chapter does not handle 'V' (no matching branch). It is effectively a no-op on the firmware as currently written, or reserved for a future “valid frame / heartbeat” feature.

Protocol summary (PC → STEPico)

Character(s)Meaning on PC side
1 then 0–5Hand slot 1 count
2 then 0–5Hand slot 2 count
RSent when only one hand is present
LSent when no hands are present
VSent every frame after other traffic

16. Errors & Cleanup (lines 172–182)

After the vision try body, dedicated handlers cover port failures and Ctrl+C; a finally always frees the camera, serial port, and OpenCV windows.

Lines 172–174 
except serial.SerialException as exc:
    print(f"Serial error on {port}: {exc}")
    print("Close Thonny/Serial Monitor, end leftover python.exe, or unplug/replug the board.")

Catches PySerial failures such as “Access is denied” / port not found when opening or using the COM device. Prints the underlying exception and a short troubleshooting hint aimed at the usual Windows conflict: another app (Thonny’s serial monitor, a previous hung Python process) still holds the port.

Lines 175–176 
except KeyboardInterrupt:
    print("\nInterrupted — releasing camera and serial port.")

Handles Ctrl+C in the terminal. Without this, an interrupt during the loop would still reach finally, but the message makes it explicit that resources are being released intentionally.

Lines 177–182 
finally:
    if serial_connection is not None and serial_connection.is_open:
        serial_connection.close()
        print(f"Closed {port}.")
    cap.release()
    cv2.destroyAllWindows()

Always runs — on normal q quit, serial open failure, Ctrl+C, or other exceptions that leave the try. Steps:

  • Close the serial port only if it was successfully constructed and is still open (avoids errors when open failed and serial_connection is still None)
  • Print confirmation that the named port was closed
  • Release the webcam via cap.release()
  • Destroy all OpenCV windows

The MediaPipe Hands context manager closes itself before this finally runs when the with block exits normally; if serial open failed before entering with, Hands was never created.

18. Usage Notes

Requirements

  • Python 3 with opencv-python, mediapipe, numpy, pyserial
  • A working webcam at index 0 (or change the VideoCapture argument)
  • STEPico (or compatible board) connected on the configured COM port, running the companion firmware
  • COM port free — close Thonny’s serial monitor and any leftover Python processes before running

Run

python ch4-finger-detection-pc.py

Press q in the OpenCV window, or Ctrl+C in the terminal, to quit. Either path runs finally so COM4 is released.

Known quirks in this source

  • landmark (line 4) and time (line 6) are unused imports
  • Hand 1 vs hand 2 is detection order, not guaranteed left/right handedness
  • No-hand state sends L (all left LEDs on), not “all off”
  • Single-hand state also sends R (all right LEDs on per firmware)
  • V is written every frame but not handled in the current STEPico script
  • COM port is hard-coded to COM4
